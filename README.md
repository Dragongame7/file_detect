# Folder Sentinel

Windows用のフォルダ追加通知アプリです。PC内や共有フォルダを複数登録し、サブフォルダを含むファイルの追加をデスクトップ通知でお知らせします。

リポジトリ名・作業フォルダ名は`file_detect`、アプリ名はFolder Sentinelです。

[配布ファイルをダウンロード（GitHub Releases）](https://github.com/Dragongame7/file_detect/releases/latest)

## 使い始める

### セットアップ版

1. `FolderSentinel.Setup.exe`を起動します。
2. 自動起動の設定を選び、「インストールして起動」を押します。
3. 「フォルダを追加」からパスと通知タイミングを保存します。

現在のWindowsユーザー用に、`%LOCALAPPDATA%\Programs\FolderSentinel`へインストールします。Node.js、Python、.NET、Windows App Runtimeの個別インストールは不要です。必要な実行要素は配布物に同梱しています。

### 展開して使う版

`FolderSentinel-1.1.1-win-x64.zip`をPC内の任意のフォルダにすべて展開し、`FolderSentinel.exe`を起動します。EXEだけでなく、展開されたDLLなども同じ構成のまま保管してください。初回の通常起動では自動起動を登録します。アプリの設定画面で無効にできます。

自動起動や通知クリックに使用するため、起動後はアプリの配置場所を移動しないでください。移動する場合は自動起動をいったん無効にし、移動先で再度有効にしてください。

## 通知の設定

- **追加を検知したら通知**：追加ファイルのサイズと更新時刻が安定した後に通知します。
- **指定日時にまとめて通知**：毎日、複数曜日を選んだ毎週、日にち・月末を指定する毎月の通知を設定できます。
- 両方を有効にすると、即時通知済みのファイルも定期通知に含まれます。
- フォルダごとに複数の定期通知予定を登録できます。予定ごとの集計は独立しています。
- 時刻は「時」「分」を選択します。09:00・12:00・18:00はボタンで設定できます。既存の予定の時刻も1分単位で引き継ぎます。
- 初回登録時の既存ファイルは通知しません。初回の基準取得中に確認したファイルも既存扱いです。
- 新しい予定は、予定を保存した後に確定した追加分から集計します。予定の日時を変更した場合は、未集計分を引き継いで次の予定から報告します。
- 予定時刻にアプリが停止していた場合は、起動後の確認が完了してから未集計分をまとめて通知します。
- 変更がない期間の通知は出しません。

通知の見出しは、設定したフォルダの**表示名**です。たとえば、次のように表示します。

```text
共有資料
新しいファイルを3件検出しました
見積書.xlsx、議事録.docx（ほか1件）
```

定期通知では件数の行に「（定期通知）」を付けます。通知をクリックすると、その表示名に紐づく監視フォルダを開きます。

## 常駐・履歴・共有フォルダ

- 設定画面を閉じても、タスクトレイで監視を続けます。完全に停止する場合はトレイの「終了」を使用します。
- 自動起動はサインイン時です。サインイン前の監視は行いません。
- 履歴画面では最新1,000件を検索・表示します。DB内の過去履歴は自動削除しません。
- 「CSV出力」は検索条件に一致する全履歴を出力します。検索欄が空なら全件が対象で、1,000件の表示制限は適用しません。UTF-8 BOM付き・CRLFのCSVで、検出ID、フォルダ名、監視パス、相対パス、検出・確定日時（PCのローカル時刻とUTCオフセット）、通知状況を保存します。Excelで数式として解釈される先頭文字の値には、文字列として扱うためのアポストロフィを付けます。
- 「履歴をリセット」は、確認後に全フォルダの追加・通知履歴と未送信通知を削除します。検索条件には限定されません。監視先の実ファイル、フォルダ設定、通知予定、既存ファイルの判定情報、コピーの安定確認中の候補は保持します。送信済みのWindows通知と障害調査用の`logs`は対象外です。必要な履歴は先にCSVへ保存してください。
- 停止中の追加も、起動時点でファイルが残っていれば検出します。停止中に追加・削除まで完了したファイルは復元できません。
- 共有フォルダはUNCパス（`\\server\share\folder`）を推奨します。現在のWindowsユーザーの権限でアクセスします。
- 接続不可の場合は前回状態を保持し、自動で再接続を試みます。
- 名前変更・更新・削除では通知しません。監視範囲外から移動してきたファイルは追加扱いです。
- 同一パスの置き換えは更新扱いです。一度削除が確認された後、同じ場所に追加されたファイルは新規追加扱いです。
- 親子フォルダなど、監視範囲が重なる登録はできません。
- ジャンクション、シンボリックリンク等の再解析ポイントは追跡しません。

## 動作環境と確認範囲

- 配布対象：Windows 10／11、x64。
- Windows 10はアプリで使用するAPIに合わせてバージョン1809以降を前提とします。OS・.NETの公式サポート条件はエディションやバージョンによって異なります。
- 開発端末ではWindows 11（ビルド26200）でビルド、画面操作、ローカル監視、Windows通知送信を確認しています。
- Windows 10実機、前提ランタイム未導入のクリーンVM、実際のNAS／ファイルサーバーでの互換性試験は別途必要です。これらの試験に合格したとするものではありません。
- ファイルIDが取得できないファイルは状態欄に読み取りエラーを表示し、名前変更を判定できたものとして通知しません。共有サーバーのIDが再接続や再起動をまたいで安定するかは、対象環境で確認してください。
- コピーの安定確認は2秒間隔・3回・4秒以上を基準とします。転送の一時停止と厳密なコピー完了を区別する保証はありません。
- ファイルイベントを受信したら差分確認します。定期的な全件確認はローカル15分、UNC共有30分、イベント監視を開始できない場合は30秒を基準にします。大規模フォルダの対応上限は未確定です。
- 通知の「OS送信済み」はWindows APIが受け付けた状態です。Windowsの通知設定や応答不可モードによって画面表示が抑制されることがあります。
- 配布EXEは未署名です。

## 保存先とアンインストール

設定・前回状態・追加／通知履歴は`%LOCALAPPDATA%\FolderSentinel\state.db`、ログは同フォルダの`logs`に保存します。監視対象ファイルの本文は保存せず、監視先のファイルを変更しません。

セットアップ版はWindowsのアプリ一覧からアンインストールできます。アプリをトレイから終了してから操作してください。監視先のファイルとユーザーデータは残します。アンインストーラー自身を実行するため、一時フォルダ内にヘルパーが残る場合があります。

展開版は自動起動を無効にしてアプリを終了した後、展開したフォルダを削除できます。通知登録も解除したい場合は、終了後に`FolderSentinel.exe --unregister-notifications --no-startup`を実行してから削除してください。

## 開発とビルド

開発環境だけで.NET 10 SDKを使用します。利用端末では不要です。

```powershell
git clone https://github.com/Dragongame7/file_detect.git
cd file_detect
```

```powershell
# SDKを作業フォルダ内に準備（開発時のみ）
.\scripts\bootstrap.ps1

# テスト、自己完結型アプリ、セットアップ、ZIPの生成
.\scripts\build.ps1

# セットアップから展開し、同梱ランタイムでの起動・通知初期化を確認
.\scripts\smoke-test.ps1
```

成果物は`artifacts`に作成します。SDK／NuGetの初回取得にはインターネット接続が必要ですが、配布アプリの導入・起動時に依存ファイルをダウンロードしません。

```powershell
# テストだけ実行
.\.tools\dotnet\dotnet.exe test .\tests\FolderSentinel.Tests -c Release

# 通常の保存先や自動起動を変更せずに動作確認
.\artifacts\FolderSentinel-win-x64\FolderSentinel.exe --data-dir .\artifacts\sandbox-data --no-startup
```

`--data-dir`で指定したデータは通常のデータと分離し、自動起動は登録しません。Windows通知の登録はテスト実行時にも行うため、配布場所を変更した後は最終配置のアプリを起動して登録し直してください。

主なソース：

- `src/FolderSentinel.Core`：追加判定、スケジュール計算、SQLite保存。
- `src/FolderSentinel.Desktop`：WPF画面、Windows通知、常駐・監視。
- `src/FolderSentinel.Setup`：依存要素を含むアプリの展開、ショートカット、自動起動、アンインストール。
- `tests/FolderSentinel.Tests`：判定・日時計算・保存・ローカル監視のテスト。

ソース側の確定要件は`requirements.md`、設計上の検討は`implementation-plan.md`、検証結果は`verification.md`を参照してください。
